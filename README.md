# Nirmaan Watch — Code Crew

A full-stack MPLADS monitoring and anomaly-review application for SIH26102. It combines a geographic project register with budgets, contractors, citizen reports, documentary evidence, and explainable screening.

## Working features

- Interactive OpenStreetMap map with project markers, pan/zoom, fit-to-projects, keyboard controls, filters, and explicit handling of missing coordinates.
- Project profiles with dates, ownership, source references, physical progress, milestones, and payment registers.
- Separate initial estimates, sanctions, contract values, revised budgets, fund releases, and expenditure. Budget balances do not imply cash available.
- Contractor profiles derived from project records, with delivery counts and project-specific community ratings.
- Authenticated feedback, owner responses, issue status, and persistent audit history.
- Project evidence upload/download (PDF, PNG, JPEG; 5 MB limit) backed by private R2 object storage. Uploaded files are labelled unverified.
- Owner-only CSV/JSON imports with validation and preview; stable work IDs update existing records. CSV preserves detailed registers unless JSON explicitly replaces them.
- Owner project updates with prior values recorded in the audit trail.
- Explainable rule checks, a seeded unsupervised Isolation Forest, and reviewer decisions. Changed project records generate fresh alert identities.
- Reports by category/district, CSV project export and JSON analysis export.
- 25 explicitly synthetic demo projects, isolated from imported records. Demo records use a fixed analysis date of 2026-09-05; imported data uses the current date.

## Stack

React 19, TypeScript, Vinext/Vite, Shadcn/Radix accessible primitives, Lucide icons, Cloudflare Workers, Drizzle ORM, D1 (SQLite), and R2. No paid AI API key is needed for the included anomaly model. Runtime declarations are generated by Wrangler. Sites owns the logical `DB` and `BUCKET` provisioning.

## Running and validating

Node 22.13+ and the Linux commands used by the supplied scripts are required.

```bash
npm run install:ci
npm run db:generate # only after changing db/schema.ts
npm run build
npm run test:domain
npm run test:api
```

`npm test` performs the build and both application test suites. API tests use an isolated local Worker/D1/R2 runtime and synthetic test identities; they do not call deployed services. The test script creates its database from the migration in `drizzle/`. If later migrations are added, extend migration loading accordingly.

The development command is `npm run dev`; the hosting environment uses its supervised preview workflow when browser QA is requested. Authentication is provided by the Sites platform. In a standalone deployment, an identity provider and a trusted header-injection gateway must be configured; never accept user-supplied authentication headers from the public internet.

## Data contract

The Data workspace includes an empty CSV template, a labelled JSON structure example, row validation, and a field guide. Money is numeric INR, not lakh/crore units; dates are YYYY-MM-DD. `DEMO-` IDs are reserved. Provide both coordinates or leave both empty. Do not substitute zero for missing financial data. Required budget fields must be supplied before importing a project; unknown optional values use null.

Payments and milestones are arrays available through JSON. A blank CSV template does not contain their columns. The JSON example contains fictional values and must be replaced with source data before real use. Imports support up to 500 rows and 2 MB per request; workspace capacity is 5,000 projects. Initial scope is five construction categories (Roads, Education, Water, Health, Community); extend the schema and UI together for other types of MPLADS work.

Your dataset and supporting documents are still required. There is no connected official government feed, automatic geocoding, OCR, or satellite-based construction-progress inference. Manual refresh/import reflects source updates; the interface does not imply live ground observation.

## Detection and interpretation

`lib/analytics.ts` implements:

1. Expenditure above revised approval (or original sanction when no revision exists).
2. Expenditure above recorded fund releases.
3. Spending ratio more than 30 percentage points above reported physical progress.
4. Non-completed work over 30 days past its planned completion date.
5. Source updates older than 60 days.
6. Repeated invoice references for the same vendor within a work record.
7. Unit-cost outliers above 1.5× the median of at least four same-category/state/unit peer projects started within one year. This is a screening comparison; engineering specifications must still be reviewed.
8. Isolation Forest: 64 random partition trees, sample size up to 128, deterministic seed, threshold 0.65. Features: log estimated cost, spending/sanction ratio, difference from a linear schedule baseline, and overdue days. Requires at least 20 projects with known progress and positive sanctions. Complexity and location are not fully modelled.

This is an implemented unsupervised detector, **not a trained or validated fraud classifier**. A score is not a fraud probability. Rule thresholds and the ML cutoff are provisional. Labelled audit outcomes and representative data are necessary to measure precision/recall and tune false positives. Public ratings are not inputs to fraud detection. No person or contractor is declared fraudulent by this application.

## Access and data protection

The initial deployment is private to the owner. The first authenticated visitor is bound atomically as workspace owner under that owner-only access policy; do not make a new instance public before its intended owner initializes it. Other authenticated visitors can submit feedback and evidence if Site access is later granted; only the bound owner can import, edit project data, respond, or review alerts. Authenticated identities are read through the bundled platform helper. Workspace records and documents require authentication; mutation endpoints reject cross-origin browser requests. SQL is parameterized through Drizzle. Document types are checked by file signature, and downloads use attachment disposition plus nosniff. Files are not virus-scanned or OCR-processed. Audit history is append-only through the application API, but is not a cryptographically tamper-proof ledger. Production governance, retention policy, and wider institutional role management need agreement before external rollout.

## Source layout

- `app/dashboard.tsx`: the eight application views and forms.
- `app/project-map.tsx`: geographic tile/marker interaction.
- `app/api/workspace/route.ts`: records, imports, ownership, reviews, updates, feedback.
- `app/api/documents/route.ts`: authenticated R2 upload/download.
- `lib/domain.ts`: schema, CSV parsing, formatting and import validation.
- `lib/analytics.ts`: rule engine and Isolation Forest.
- `lib/demo.ts`: isolated, fictional demonstration records.
- `db/schema.ts`, `drizzle/`: persistent tables and SQL migrations.
- `tests/`: application checks plus retained starter component tests (not part of the application smoke suite).

## Bilingual civic design

The interface includes Hindi–English navigation and headings, restrained tricolour accents, and a public-works banner inspired by the supplied reference. It is explicitly labelled as the Code Crew SIH prototype. This is bilingual supporting copy, not a full language-switching translation.

The project-owned transparent asset `public/images/public-works-montage.png` (2172 × 724, RGBA) was generated using the built-in image-generation tool. Prompt: realistic editorial infrastructure montage for an Indian public-works monitoring prototype, viaduct, spillway, institutional building, two helmeted Indian engineers, muted daylight and teal/navy tones, subjects on the right, transparent left third and feathered edges, no logos, flags, emblems, or text. The artwork is illustrative and is not evidence of a real project.

Scroll reveals use IntersectionObserver; all content remains visible if it is unavailable. Buttons have restrained hover/press effects and map navigation retains its own interaction behaviour. Smooth scrolling and motion are disabled when the visitor requests reduced motion.
